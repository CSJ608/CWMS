# ADR-0007 配置 schema 与 overlay 合并语义

状态：已接受 ｜ 日期：2026-08-28 ｜ 关联：issue #3、ADR-0002

## 背景

ADR-0002 立了配置分层的规矩（简单场景免费、复杂度按需付费、配置项预算制），
但规矩停在文档里：插件的配置是裸参数，无 schema、无校验、无合并语义。
本 ADR 把它机制化——**schema 声明在插件身上，解析发生在内核挂载时**。

## 决策

1. **schema 是插件声明的一部分**（`Plugin.configSchema`）。`mount(plugin, overlay)`
   时内核统一解析：零配置 → 全默认；overlay → 深合并；违约 → `ConfigError`
   聚合报出所有违规项（带键路径），不报一个停一次。
2. **合并语义**：
   - **record 逐键深合并**——新增冷链区 S 只写 `{ zonePriority: { S: 0 } }`，
     缺省表保留。"加一个区域不必抄全表"就是简单场景免费的反面：复杂场景
     只为增量付费。
   - **标量与数组整体替换**——数组拼接的语义（去重？定位覆盖？）是含糊的，
     含糊的选择不如没有选择。
3. **未知配置项是错误，不是警告**。拼错的键静默失效，比让它上线昂贵得多；
   同时它是配置预算制的执行点——新增配置项必须先改 schema（过 ADR-0002
   论证），overlay 里塞不认识的键过不了门。
4. **默认值写进 schema**，apply 永远收到解析后的完整配置——插件代码里
   不再出现 `config?.xxx ?? yyy` 的默认值散落。
5. **reload 是原子的**：新配置解析失败时先抛错，旧实例保持在岗
   （否则一次拼写错误会让策略整条下线）。
6. 无 schema 插件保持透传，向后兼容。

## 后果

- "零配置可用"与"overlay 生效"成为框架级测试设施：任何 schema 插件
  的验收测试都有统一的写法（见 feat-inbound 测试的配置 describe 块）。
- 配置面有了单一事实来源：想盘点全系统有多少配置项，数 schema 即可。
- v0 只覆盖五种字段类型（int/string/bool/stringArray/recordOfInt）；
  新类型随真实需求加，不预先设计通用 schema 语言。
