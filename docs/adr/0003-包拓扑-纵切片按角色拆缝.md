# ADR-0003 包拓扑：纵切片，按角色拆缝

状态：已接受 ｜ 日期：2026-08-28

## 背景

"前端界面的模块化和后端接口的模块化，是否有必要一个一个包的形式提供？"
这个问题预设了切法：按端切。参照 DeepSeek Harness 的拓扑原则，切法应该是第三根轴。

## 决策

1. **包 = 插件 = 纵切片**。一个功能包同时携带 host 半身（服务/事件）与
   client 半身（UI 描述符）。前端模块和后端服务不是两套包体系，
   是同一个功能的两半——只要它们共同演化。`feat-inbound` 是范本。
2. **拆包依据是角色，不是层**：当 Service Definition / Provider / Consumer
   需要独立演进时才拆成不同包（策略缝是模板：接口在 contracts，
   zone/abc/veto 各自成包）。单一用途的插件保持一个包。
3. **contracts 是唯一必拆的横切包**：前后端之间、内核与插件之间、
   系统与外部世界之间，只通过契约对话。契约包集中领域类型、服务 key、
   事件契约、客户端描述符。
4. **依赖方向铁律**（违反即架构事故）：
   - 功能与策略只准依赖 `contracts` + `kernel`（及其 inject 的服务接口）；
   - 内核不 import 任何策略——"没有任何一行修改循环本身"是可验证的断言；
   - 所有 client 半身只通过 contracts 对话。
5. **有第二个消费者之前不拆包；接口未稳定之前不立缝。**
   晚拆是一次重构，错拆是十年还债。

## 后果

- v0 只有 9 个包。包数量的增长必须由"第二个实现/消费者出现"驱动，
  不由对称感驱动。
- 每个 README/包头的职责声明是约束的一部分；CI 的依赖检查是未来项
  （见 issue：依赖方向自动化守卫）。
