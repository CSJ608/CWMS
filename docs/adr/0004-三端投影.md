# ADR-0004 三端投影：PC/PDA/大屏是同一领域的三种函数

状态：已接受 ｜ 日期：2026-08-28

## 背景

WMS 有 PC 端、PDA 端、数据大屏。直觉做法是做三套界面体系、三个前端模块化维度。
错误：三端不是三个系统，是**同一个领域模型的三种投影**：

- **PC 交互是数据的函数**——表格、表单、流程审批；
- **PDA 交互是任务的函数**——一步步扫码-校验-执行，推进一个任务状态机；
- **大屏交互是指标的函数**——只读聚合。

## 决策

1. **领域只写一份**，在 host 半身；各端拿走自己的投影。
2. **PDA 不做"每功能一套页面"，做通用扫码工作流引擎**：步骤定义、扫码焦点、
   离线队列、幂等重传沉淀在 runtime（未来包）；功能包只向注册表登记
   **工作流描述符**（`PdaWorkflow`，纯数据）。这是三端里 ROI 最高的投资：
   一致性、弱网、焦点管理全部一次解决，功能只剩十几行声明。
3. **大屏定为只读投影缝**：领域事件 → 物化读模型 → 卡片描述符。
   立纪律：大屏永不直查业务表。`projection-dashboard` 插件是范本。
4. **client 半身是描述符，不是页面**。功能包永远不知道端的细节；
   各端 runtime 消费描述符渲染。

## 后果

- 新增一个端 = 写一个消费描述符的 runtime，功能包零改动。
- PDA runtime 与离线同步是真实基建，排期在 issues 中跟踪，不混入功能包。
- 描述符 schema 的演进是契约变更，走 contracts 包的 PR + ADR。
