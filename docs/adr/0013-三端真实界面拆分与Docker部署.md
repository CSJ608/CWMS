# ADR-0013 三端真实界面拆分与 Docker 部署

日期:2026-08-31 ｜ 状态:已接受

## 背景

`apps/web` 用单页在同一屏幕上并排三个面板(PC 表格 / 大屏看板 / PDA 扫码模拟器),验证了三端投影命题(ADR-0004),但混淆了「端」的边界:真实环境里 PC 与大屏是不同人群在不同设备打开的不同界面,PDA 是手持机上的应用——且扫码枪的广播/Intent 输出(行业主流 DataWedge 模式)浏览器根本接不住,PDA 必须是原生应用。

## 决策

1. **界面拆分**:单页退役。拆为两个静态页——`/pc`(操作台:入库/出库表单 + 表格投影 + 任务轨迹)与 `/board`(大屏:只读的指标卡片 + 作业看板);PDA 模拟器面板退役,其会话工作流语义由原生安卓应用承接(`apps/pda-app`,另行 PR)。三端仍是纯消费者,`/api` 契约零改动。
2. **本地与部署双形态**:本地 `pnpm web` 单进程直接服务两页(零依赖开发体验不变);部署走 `docker-compose` 两服务——`backend`(组合根 API,即 apps/web 的 server)+ `frontend`(nginx 静态两页并反代 `/api`)。
3. **不引入新缝、新契约**:部署拓扑不是架构缝——frontend 只做静态与反代;PDA 应用直连 `/api`;内核与包拓扑零改动。
4. **内存态照旧**:PoC 不做持久化(ADR-0011 的拆缝条件未触发),容器重启即清空,演示可接受。

## 后果

- 正面:端的边界=部署边界,「换 UI = 换渲染器」从单页内三个 div 变成三个独立交付物;PDA 原生化后扫码枪广播、震动反馈、扫码优先交互才可能落地。
- 负面/限制:两页共享样式靠复制(零构建理念的代价,页面拆多后再议共享方案);nginx 反代多一跳;内存态下 backend 重启丢数据;PDA 应用引入安卓构建链(JDK/Gradle/SDK),CI 暂不覆盖 APK 构建。

## 附注(构建环境事实,2026-08-31)

- **基础镜像走 daocloud 镜像源**(`docker.m.daocloud.io/library/node:22-alpine`、`…/nginx:alpine`):本机所在网络对 Docker Hub(registry-1.docker.io)直连不可达,镜像源选择是环境事实而非架构偏好;在可直连的环境可等价替换为官方镜像名。
- **`/` 的两形态行为**:本地 node 形态 302 → `/pc`(server.ts);Docker nginx 形态 `location /` 直出 pc.html(200)。两种形态用户可达结果一致(都是 PC 操作台),差异仅在响应语义。
