# ADR-0010 大屏投影：卡片查询绑定与作业看板读模型

状态：已接受 ｜ 日期：2026-08-28 ｜ 关联：issue #16、ADR-0004/0006/0009

## 背景

ADR-0004 定义三端投影：PDA 是任务的函数（PR #9）、PC 是数据的函数（PR #9/#13），
大屏是**指标的函数**。此前大屏只有 feat-inbound 里的一个临时读模型
（todayInboundQty），没有端 runtime，也没有 task/changed 驱动的作业看板。
本 ADR 落地第三端，三端收官。

## 决策

1. **卡片引擎完全复刻 pc-runtime 模式**：`DashboardRuntime` 消费 `DashboardCard`
   描述符，`query(cardId)` 组装 `{描述符 + 指标值}`；指标数据源由组合根
   `bindMetric(metric, provider)` 绑定。未注册卡片、未绑定指标均大声报错——
   与 pc-runtime 同语义。**runtime 纯机制，指标怎么算是组合根的事**。
2. **作业看板是事件喂养的物化读模型**：`taskBoardPlugin` 订阅 `task/changed`，
   维护按状态分列的视图（计数 + 任务清单）。大屏**永不直查任务机**——
   投影跟随事件，不跟随查询。卸载即重置（`ctx.effect`，可逆性纪律 ADR-0001）。
3. **看板住在 dashboard-runtime，不住在功能包**：任务机是领域无关内核
   （ADR-0005），它的状态分列投影同样是领域无关机制；功能的看板语义
   （哪些 kind 值得上墙）将来由卡片/描述符表达，不预先设计。
4. **无实时推送/节流/历史曲线**：投影按需付费（ADR-0002）。
5. **依赖守卫补漏**：check-deps 的角色规则此前未覆盖 `client-registry` /
   `pda-runtime` / `pc-runtime`（意外豁免）。新增 **runtime 角色**（只准
   contracts + kernel，与 core/plugins 同约束），dashboard-runtime 出生即被守卫覆盖。

## 后果

- 三端投影收官，共享同一模式：**描述符注册表 + 组合根绑定 + 查询/事件语义**。
  换大屏 UI = 换一个消费 `CardView`/`TaskBoardView` 的渲染器，功能包零改动。
- feat-inbound 的 `dashboardProjectionPlugin`（todayInboundQty）保持原位：
  它是功能级读模型（领域语义），runtime 只认组合根绑定的 provider——层次不混。
- TaskBoard 的列清单取自 TaskStatus 契约；出现"自定义列/泳道"真实需求时再扩描述符。
