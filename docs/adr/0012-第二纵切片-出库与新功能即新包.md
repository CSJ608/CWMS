# ADR-0012 第二纵切片：出库与新功能即新包

状态：已接受 ｜ 日期：2026-08-29 ｜ 关联：issue #23、ADR-0003/0004/0005/0011

## 背景

「一切皆插件」此前只有一个纵切片（feat-inbound）作证。单功能规模下
"新功能不改核"是无法证伪的——所有缝都可能是为唯一用户定制的。
第二个功能（出库/拣货）是对包拓扑（ADR-0003）与三端投影（ADR-0004）
的真正压力测试。

## 决策

1. **出库 = 一个新包** `packages/features/feat-outbound`，与 feat-inbound
   同构：host 半身（OutboundService）+ client 半身（三端描述符）+ 功能级
   读模型（outboundProjectionPlugin，订阅 `ledger/changed` 的 ship 事件）。
2. **零改动内核与端 runtime**：任务机复用（kind='pick'，迁移表与 opId 幂等
   原样适用）、账本 ship 通道复用（库存不足否决是 core-ledger 的内核不变量，
   不是策略）、PDA/PC/大屏三个 runtime 原样消费新描述符。命题的可执行
   证明 = `git diff main -- packages/kernel packages/core-* packages/client-registry
   packages/*-runtime` 为空。
3. **contracts 只做词汇表扩展**：OUTBOUND 服务 key、OutboundLine（与
   ReceiptLine 同形，结构化匹配）、DashboardCard.metric 增加
   'todayOutboundQty'、InventoryLedger.ship 参数改用 OutboundLine（同形
   非破坏）。既有类型不改名、不改形。
4. **不新增策略缝**：拣货路径/波次排序等无第二实现（准入五问不过）；
   出库功能不引入任何缝。缝的数量保持：putaway/decide 一个。

## 后果

- 命题"新功能即新包"首次得到可执行验证；此后每个新功能 PR 都应附带
  "内核零 diff"证明，回归即拓扑退化的报警。
- 第二个功能没有推翻任何缝设计——但也只证明了一件事：**纵向扩展通畅**。
  功能间交互（如收货触发出库需求、跨功能事务）尚未出现，等真实需求。
- ship 的 OutboundLine 与 ReceiptLine 同形是刻意的：等第三个功能出现
  再决定是否提炼共同的行类型，现在提炼是预设计。
