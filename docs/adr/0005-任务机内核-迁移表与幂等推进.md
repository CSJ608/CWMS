# ADR-0005 任务机内核：显式迁移表与 opId 幂等推进

状态：已接受 ｜ 日期：2026-08-28 ｜ 关联：issue #1

## 背景

WMS 的作业本质是任务流：收货上架、拣选、补货、盘点都是一次任务推进。
PDA 在弱网环境下的扫码重试是常态——**同一次操作可能被提交多次**，
任务机必须保证重复提交不产生重复效果（不重复扣账、不重复推进）。

ADR-0001 已把任务状态机预告为内核封闭清单成员。本 ADR 落地其语义（`core-task` 包）。

## 决策

1. **属于内核，不开放实现缝**。"可替换的任务机"与"可替换的账本"同级灾难：
   迁移语义是全系统作业一致性的根基，只有一种实现。
2. **领域无关**。kind 只是字符串（`putaway`、`pick`…）；"上架"的全部语义
   （策略瀑布、账本移动）住在 feat-inbound 里，由它驱动任务机。
   任务机不知道任何领域词汇——这是"内核不 import 策略"的对称面：
   **内核也不理解策略**。
3. **显式迁移表**：
   `created → assigned → executing → completed`；
   `created / assigned / executing` 可 `cancelled`；终态拒绝一切新迁移。
   跳步、自环（新 opId 重复同一迁移）一律拒绝——**重放保护只有 opId
   一条路**，绕过它重复推进是 bug，要暴露而不是吞掉。
4. **幂等 = opId**。每次推进携带操作 id：重放返回该操作完成时的快照，
   不重复执行、不重复发事件；**opId 跨任务复用立即报错**（它是 bug 信号，
   不是重放）。实现为全局 op 索引 + 每任务 op 快照表。
5. **事件**：`task/changed`（emit 模式）记录 `from/to/opId`，
   `from: 'void'` 表示创建。投影（大屏任务看板）与取消补偿都是它的监听者。

## 后果

- PDA 弱网重试安全：集成测试断言"同 opId 重放 → 结局相同、账本总量不变"。
- 取消的补偿（如把已收暂存的货退回）是功能包监听者的责任，内核不做补偿。
- v0 为内存实现，存在崩溃窗口（create 之后进程终止则任务悬挂）；
  由未来持久化 provider 缝解决，不阻塞语义设计。
- 开发中发现的缺陷记录：初版 `#replay` 未校验任务身份，跨任务 opId 复用
  被静默当作重放——由"opId 跨任务复用立即报错"这条测试逼出并修复。
  这正是"拒绝语义必须有测试断言"的价值。
